# Cyrus: отчёт о редизайне

## Основа и статус

Изменён архив `Cyrus-2026-09-19.zip` из `Eren2932/Cyrus`, дерево репозитория `b21ee0e72b17f1e6a042240408c839ab170cc364`, blob архива `7a516f6179f223aa027cf298a46c4687054f74cd`. Git SHA-1 содержимого проверен после загрузки через GitHub API.

Это результат работы с **реальным Jetpack Compose-проектом**, а не HTML-макет. В GitHub ничего не записывалось, Actions не запускался, APK не собирался. Архив содержит весь изменённый проект. Изменения на устройстве пока не проверены.

## Главный экран

Убраны название Cyrus, камуфляж, декоративные уголки кнопки и сами файлы обоев. В тёмной теме фон действительно чёрный, а поверхности имеют графитовые оттенки. Светлая тема и системная настройка сохранены, но без прежнего рисунка.

Кнопка питания теперь компактная, с оранжевым непрозрачным кольцом, белым значком в отключённом состоянии и ненавязчивым рисованным ореолом. Подпись показывает реальное состояние туннеля, а не статический текст референса. Сохранены VPN-разрешения, запрос разрешения уведомлений и существующие connect/disconnect use case. При наличии достоверных счётчиков после подключения выводится компактная строка трафика.

Серверы перенесены на главную. Панель раскрыта по умолчанию, сворачивается нажатием на шапку или вертикальным жестом по шапке. Состояние панели, запрос поиска и позиция списка сохраняются при переходах. Во время сворачивания строки остаются рисуемыми под обрезкой, но сразу теряют доступность для нажатий и TalkBack. Нижний бар находится вне панели и не участвует в её измерении.

`LazyColumn` имеет ограниченную высоту и стабильные ключи. Большая коллекция серверов не превращает весь экран в бесконечную колонку. Для низкой доступной высоты, в том числе при клавиатуре, действие подключения переносится в шапку панели; основной control не должен перекрывать поиск. Это реализовано в коде, но требует проверки на Android.

## Реальные данные, а не демонстрационные страны

Список берётся из `ProfileRepository`. Серверов Германии/США и красивых чисел из референса в production-данных нет. Пустая библиотека предлагает импорт ключа. Поиск работает по имени профиля, распознанному названию страны и коду страны.

Регион — только подсказка из явного флага/кода/названия в имени импортированного профиля. Геолокация по IP не заявляется. При неизвестной стране остаются исходное имя и нейтральная планета. Для нескольких ключей одной страны дополнительная строка сохраняет имя профиля. Пять флагов из референса нарисованы векторно, прочие явные региональные метки используют системный флаг.

Измерения используют существующий `LatencyProber`, максимум четыре работника и 2000 мс тайм-аут на измерение. Есть первоначальный замер и кнопка обновления в поиске; бесконечного опроса нет. «Нет ответа», «Без замера» и неизвестная задержка — разные состояния. Полоски не изображают хороший сигнал, когда измерения нет. RTT означает доступность конечного адреса, **не скорость, не качество и не подтверждённую работоспособность VPN**. Замер может зависеть от текущего сетевого маршрута.

Выбор в отключённом состоянии сохраняет профиль, не включая VPN. При активном соединении используется существующий `ConnectUseCase`; во время подготовки, остановки или автовыбора конкурирующий выбор блокируется. Выделение подключённого сервера берётся из фактического `TunnelState.Connected.profileId`.

## Геометрия и графика

Ориентир — чёрное изображение 692 × 1536. Геометрия реализована в Android dp/sp с учётом insets, поэтому буквальное совпадение пикселей нельзя установить без плотности конкретного устройства и скриншота собранного приложения. Увеличенный текст и добавленная кнопка замера намеренно отличаются от референса.

|---|---|
| Фон | `#000000` |
| Акцент | `#FF7908` |
| Основной текст/планета | `#F4F5F5` в тёмной теме |
| Панели | `#090B0C`, `#111416` |

Планета намеренно нейтральная, без оранжевого тонирования. Значки рисуются через Canvas, с согласованной толщиной и скруглениями. У щита переработан контур; добавлены собственные планета, поиск, обновление и шеврон.

Навигация сохраняет мгновенную смену выбранного пункта. Оранжевый индикатор движется в graphics layer, не изменяя ширину слотов. Иконки рисуются нейтральными вне движущегося индикатора и тёмными внутри него с геометрической маской: нет независимой анимации цвета, которая даёт серый значок на оранжевом промежуточном кадре. Учтён RTL для индикатора. Частые нажатия перенаправляют текущую анимацию, а не добавляются в очередь. Android reduced motion сохранён.

## Настройки и сохранённые функции

В нижнем баре теперь «Главная», «Ключи», «Подписка», как в референсе. «Защита», «Приложения» и «Статистика» доступны из настроек, а HTTPS-инспекция — из защиты. Эти экраны не удалены.

Настройки сгруппированы в скруглённые карточки с нейтральными иконками. Часто используемые параметры подключения видимы сразу; DNS, IPv6, Multiplex, журнал и расширенная маршрутизация сворачиваются. Черновики полей переведены на `rememberSaveable`; сохранение сетевых параметров остаётся явным и проходит исходную валидацию.

## Изменения устаревших проверок и исходный риск TLS

В исходном ZIP часть guard-скриптов не соответствовала уже лежащему рядом коду. `check_source.py` запрещал любое использование `kotlin.random.Random`, хотя `data/QuicProbe.kt` применяет его для настоящего протокола. Проверка оставлена строгой для production UI и симулятора, но не блокирует реальный QUIC probe. Проверки наличия камуфляжа и его декодера заменены проверками отсутствия обоев, чёрного фона и новой панели; mutation-тесты обновлены соответственно.

**Отдельный существенный риск, существовавший до редизайна:** в `ConfigFactory.kt` присутствующий `pinSHA256` ведёт к `insecure = true`, а не к проверке отпечатка сертификата. Аналогичное поведение есть в `XrayConfigFactory.kt`. Это ослабляет защиту от подмены сертификата. Старый guard ожидал `require("pinSHA256" !in q)`, которого в архиве уже не было, и падал на исходной версии.

В этой работе сетевое поведение **не изменялось**. Устаревшая combined-assertion разделена: запрет неподдерживаемого multiMode проверяется и mutation-тестируется, а наследуемое поведение pinSHA256 явно выдаёт `WARNING`, а не ложно объявляется проверенной защитой. Этот переход от failing assertion к предупреждению сделан открыто и не является исправлением безопасности. Для производственного выпуска нужен отдельный выбор: реализовать настоящую проверку pin либо отказывать в подключении при неподдерживаемом pin. Текущий редизайн не следует считать security-approved релизом.

## Как применить

Загрузить новый ZIP в корень GitHub без распаковки и запустить существующий ZIP workflow для нового commit/имени архива. В репозитории на момент чтения workflow выбирает ZIP по истории изменений. Ни push, ни запуск Actions отсюда не выполнялись.

После успешной сборки нужен скриншот главной на том же устройстве с тем же масштабом шрифта, а затем геометрическая доводка по фактическому рендеру. Чек-лист — `docs/REDESIGN-QA.md`.
