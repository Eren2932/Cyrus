# Cyrus 0.5.0-dev: изменения поверх 0.4.2

Дата подготовки: 2026-09-18. **Статус: исходники для проверки, не стабильный релиз, не готовый APK.** Требование «любой рабочий ключ и все протоколы» этим результатом полностью НЕ закрыто.

## Основа и устройство проекта

Из публичного Eren2932/Cyrus получен snapshot main с commit `9b21478b4409037ff8aa35f6f3d48ca128f9df4d`. В нём найден `Cyrus-0.4.2-merged-full.zip`, который использован как исходная основа. Проект — Android, Kotlin, Compose, Koin, MVI; domain отделён от Room/Keystore/DataStore и адаптера sing-box. Страница магазина и документы backend не являются готовым сервером продаж.

Сохранены applicationId `dev.kentra.app`, БД `kentra.db`, схема Room, существующие настройки оформления, темы, обои и три основные вкладки. Версия повышена до `0.5.0-dev`, code 7. Ядро НЕ обновлялось вслепую: сохранён sing-box v1.11.1, commit `92d245ad040cbda2f84b21c2a847a470e532c179`. Его закреплённые Go-исходники отдельно загружены для сверки схем. Это ограничение совместимости, а не рекомендация считать старое ядро актуальным по безопасности.

## Что изменено в исходниках

Импорт дополнен SOCKS4/4a/5, HTTP и HTTPS-прокси. В окне импорта теперь явный выбор между ключами/JSON и HTTPS-подпиской: HTTPS-прокси не должен случайно интерпретироваться как URL подписки. Списки, Base64 и текстовые файлы сохранены. Добавлено извлечение отдельных VLESS/Trojan/Shadowsocks/Hysteria2-узлов из рассматриваемых Xray JSON-конфигураций и массивов конфигураций. Удалённые DNS, routing, inbounds и balancer НЕ исполняются. Исходный JSON outbound сохраняется в зашифрованном transport DTO, неизвестные поведенческие опции помечаются несовместимыми. Лимиты длины, глубины JSON и разрастания результата ограничивают затраты на обработку.

В библиотеке показываются имя узла, адрес, протокол, источник подписки, реально работающий profileId и причина известной несовместимости. Смена выбранного узла при активном соединении вызывает controller.connect, а не только меняет ID в настройках. Общий runner сериализует команды службы, отменяет старую сессию и ждёт teardown перед запуском следующей. Владение TUN-дескриптором, Mutex и NonCancellable-остановка сохранены. Ошибки ядра не выдаются пользователю с сырыми ключами. **Переключение разрывает текущие TCP/UDP-сессии; seamless-перенос соединений не реализован. При остановке VPN возможен прямой трафик: kill switch не добавлен.**

Для режима прокси добавлена отдельная foreground Service, без VPN-согласия и без TUN. Единственный mixed inbound слушает `127.0.0.1:2080` либо выбранный непривилегированный порт, не LAN. Приложения нужно отдельно настроить на этот HTTP CONNECT/SOCKS5-прокси. Это не системная защита всего устройства. Локальной авторизации нет: любой процесс на этом устройстве, имеющий доступ к сети, потенциально может обратиться к порту. Перед сменой VPN/прокси требуется отключиться. Android specialUse FGS и ограничения OEM требуют проверки; разрешение Google Play для этого типа службы не гарантируется.

В конфигурационный адаптер добавлены Hysteria2 salamander, полосы/диапазоны портов/интервал hopping; параметры TUIC congestion/UDP/heartbeat; встроенные SIP003 obfs-local/v2ray-plugin; HTTP/SOCKS outbounds. Исправлены тип `host` у HTTPUpgrade/HTTP, отсутствие лишних WS-полей у gRPC, влияние IPv6 на разрешение адреса VLESS. Per-app include/exclude теперь передаются TUN/Android Builder, а не неэффективным route package matching. Vision с включённым multiplex отклоняется явно. Доступность конкретного сервера эти изменения не доказывают.

В настройках доступны режим, локальный порт, MTU, TUN stack, IPv6, обход LAN, блокировка рекламы, multiplex, remote/local DNS, уровень логирования и списки package IDs для per-app VPN. Сохранение выполняется явно, с валидацией. Изменения применяются при следующем подключении; автоматического безопасного live-reconfigure нет. Списки приложений задаются package IDs, системный picker установленных приложений не добавлен.

Добавлен защищённый редактор: адрес, порт, UUID/пароль, TLS/SNI/ALPN/fingerprint, Reality, flow, транспорт, Host/path/serviceName и полная ссылка для дополнительных параметров. Экспорт строится из текущих полей и сохраняет неизвестные query-параметры. Есть отправка через Android share sheet с предупреждением о раскрытии секрета. Текущий подключённый ключ нельзя редактировать без отключения. Обновление подписки может заменить локальные изменения. Редактор намеренно не обещает синхронизацию с панелью провайдера.

QR-сканер — bundled ZXing Embedded 4.3.0, без внешнего распознавания и требования Google Play Services. Camera разрешение запрашивается scanner activity; снимок штрихкода не сохраняется; окно защищено FLAG_SECURE. Распознанный текст попадает в окно импорта для проверки, а не автоматически устанавливает соединение. Чтение QR из галереи и генерация QR для экспорта пока не добавлены.

Мастер VPS готовит команды для Linux/systemd: VLESS TCP/TLS (не Reality), Trojan, Hysteria2, TUIC, Shadowsocks. Пользователь выбирает стабильную версию, архитектуру и доверенную SHA-256 сумму официального Linux tar.gz. Команды сверяют checksum до распаковки, проверяют конфигурацию до установки и отказываются перезаписывать существующие файлы. Создаётся отдельная служба cyrus-proxy. TLS-сертификат должен быть подготовлен заранее. Firewall, ACME, установка системных пакетов, Reality/XHTTP, существующие панели и SSH-управление не реализованы. Команды с секретами нужно прочитать перед ручным выполнением. На реальном VPS мастер не испытывался.

## Фактические форматы предоставленной подписки

Получены пять ответов через URL-загрузчик. Ни токен, ни UUID, ни исходные приватные ответы не входят в итоговый проект. Таблица — снимок ответов в момент проверки, не универсальное поведение параметра app и не результат запуска APK.

| app | Формат ответа | Извлекаемых прокси-узлов | Что не запускается этим адаптером |
|---|---|---:|---|
| happ | Xray JSON array | 4 | HY2 с pin/специфичными QUIC-опциями, gRPC multiMode, XHTTP |
| v2raytun | Xray JSON array | 3 | gRPC multiMode, XHTTP |
| v2rayng | Base64 ссылок | 4 | HY2 pinSHA256, gRPC multiMode, XHTTP |
| nekobox | Base64 ссылок | 2 | HY2 pinSHA256 |
| hiddify | Base64 ссылки | 1 | В данном ответе — только обычный VLESS WS/TLS |

Во всех пяти случаях WS/TLS-узел предусмотрен текущим адаптером, но не проверен соединением. Отдельно предоставленный VLESS TCP Reality/Vision тоже соответствует предусмотренному пути. Гарантировать его срок действия, доступность, правильность серверной настройки и работу на телефоне по формату ссылки нельзя.

Для всех пяти вариантов созданы **обезличенные** fixtures и Kotlin-тест ожидаемого числа извлечённых узлов. Тест добавлен, но здесь не запускался. При неизвестном формате всей подписки старый набор не заменяется; известный, но несовместимый узел сохраняется и виден с предупреждением. Импорт узла не означает разрешение его запуска.

## Что остаётся нерешённым

XHTTP и gRPC multiMode требуют отдельного совместимого адаптера/ядра; у закреплённого sing-box нет требуемых интерфейсов. Для Hysteria2 pinSHA256 нужна настоящая проверка pin в ядре: замена её на insecure или простое удаление параметра недопустимы. WireGuard, OpenVPN, SSH, SSR, Hysteria1, sing-box JSON, Clash YAML/JSON и все прочие «любые протоколы» не добавлены. Это должна быть следующая отдельная multi-core работа с pinning версий, лицензиями, Go/Android API и матрицей реальных испытаний.

Один ключ обычно описывает один endpoint. Нет API для получения скрытых регионов провайдера; Cyrus показывает только узлы, фактически предоставленные подпиской, с их именами. Геолокация по IP и автоматический региональный каталог не реализованы. Имя страны в профиле — метка, не доказанная физическая локация.

Рабочий CommandServer для native-статистики по-прежнему не подключён. Вместо ложных нулей UI показывает «—», пока нет подтверждённого status sample. Нативный startup не доказывает end-to-end доступ в интернет; UI обозначает запуск интерфейса/прокси. Не добавлены автоматический health check, fallback, kill switch, периодическое обновление подписок и восстановление сессии после убийства процесса (START_NOT_STICKY выбран намеренно).

## Проверки и следующий шаг

Выполнены Python-проверки исходников, XML/TOML, исходных инвариантов дизайна и backend, мутационные проверки guard-скриптов, shell-синтаксис существующих shell-файлов, проверка структуры fixtures, сверка новых schema-полей с закреплёнными Go-исходниками, проверка упаковки и контрольных сумм. Ни одна из этих проверок не равна компиляции Kotlin или запуску VPN.

Добавлены 48 JUnit-сценариев: импорт/экспорт/JSON/лимиты, native config mapping и fail-closed, настройки, генерация серверных команд и ownership состояния службы. **JUnit не выполнялся.** В the Computer отсутствуют Gradle, Kotlin-компилятор, Android SDK и AAR; установка пакетов недоступна. APK, Android lint, native Go check, тесты на Android/VPS и реальное соединение не выполнялись.

Внутренний Android CI и прилагаемый внешний ZIP workflow запускают unit tests и lint до публикации APK; отдельно Go-бинарник из того же pinned commit проверяет синтетические конфигурации, а bash проверяет скрипты, сгенерированные JUnit. Workflow подготовлен, но не был отправлен или запущен в аккаунте пользователя.

Для существующего репозитория загрузите исходный ZIP и замените `.github/workflows/build.yml` файлом `Cyrus-build-validated.yml`. Запустите workflow с точным именем архива. Старый workflow умеет собирать ZIP, но не включает эти новые обязательные gates. Использовать APK можно для тестирования только после успешного завершения ВСЕХ шагов. Release-подпись не добавлялась; обновление 0.4.2 требует совпадающей подписи. Не удаляйте установленный клиент без безопасного экспорта ключей.

Приёмка на Android: Reality/Vision и WS/TLS с проверкой внешнего IP/DNS/TCP/UDP; каждое переключение с контролем реального трафика; Wi-Fi/мобильная сеть; ошибки TLS/порта/ключа; остановка из приложения/уведомления/системы; отказ камеры; холодный старт; режим прокси без VPN-индикатора; обновление подписки без утраты старых данных; проверка неподдерживаемых узлов; очистка ресурсов при rapid start/stop. До этих испытаний пометка dev должна оставаться.
