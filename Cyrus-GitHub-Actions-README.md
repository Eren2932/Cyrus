# Cyrus — сборка из ZIP через GitHub Actions

## Установка

1. Сначала загрузите `Cyrus-0.3.0-full.zip` в корень Eren2932/Cyrus. Старые ZIP можно оставить. Сам проект в репозитории распаковывать не требуется.
2. В GitHub выберите Add file → Create new file.
3. В поле имени укажите точно `.github/workflows/build.yml`.
4. Скопируйте полное содержимое предоставленного `build.yml`. Не вставляйте Markdown-ограждения вокруг YAML.
5. Commit changes в основную ветку main/master. Если основная ветка называется иначе, добавьте её в `on.push.branches`.
6. Откройте Actions → Cyrus APK from ZIP. Создание workflow автоматически запустит выбор последнего существующего ZIP проекта по Git-истории.

Файл `build.yml` в корне репозитория не запустится: обязательна директория `.github/workflows/`. ZIP с исходниками, напротив, остаётся обычным файлом в корне или подпапке.

Если другие активные workflow уже запускают Android-сборку по каждому push, отключите ненужные через Actions → соответствующий workflow → меню ⋯ → Disable workflow. Новый build.yml не может отключить другие workflows. Не требуется удалять архивы.

## Выбор ZIP

Обычный push: выбирается добавленный/изменённый ZIP с Android-проектом внутри. Старые неизменённые архивы не собираются. Замена содержимого под тем же именем поддерживается. Если несколько ZIP проекта изменились одним push, автоматический выбор намеренно прекращается: запускайте вручную с точным путём. Удаление ZIP само по себе не вызывает сборку старого архива — запуск завершится пояснением.

Первичная установка/изменение только build.yml или ручной запуск с пустым полем: берётся ZIP из самого свежего коммита по first-parent Git-истории, где менялся существующий архив проекта. Это не выбор максимального номера версии и не сортировка по имени. Если редактировать старый архив, он также становится изменённым; для однозначного выбора есть ручной путь.

Поддерживается проект в корне ZIP или одной папке вроде `Cyrus/`. Внутри должны быть settings.gradle(.kts) и app/build.gradle(.kts). Архив APK или ZIP с другим ZIP внутри не является проектом. Имена `.zip` используются в нижнем регистре. ZIP должен быть обычным Git-файлом, не незагруженным LFS-указателем.

## Ручной запуск

Actions → Cyrus APK from ZIP → Run workflow.

`archive`: `Cyrus-0.3.0-full.zip` (или точный путь от корня, например `releases/Cyrus-0.4.0-full.zip`). Можно оставить пустым для выбора по Git-истории.

`run_checks`: дополнительно запускает unit tests и Android lint. По умолчанию выключено; обычная сборка APK не является проверкой VPN на устройстве. APK загружается до дополнительных проверок, поэтому при падении тестов он может быть доступен, но такой запуск не считать полностью прошедшим проверку.

## Нативное ядро

Если в проекте есть один AAR в vpn/service/libs, он используется. Иначе workflow собирает sing-box v1.11.1, commit 92d245ad040cbda2f84b21c2a847a470e532c179, через штатный cmd/internal/build_libbox. Go 1.23.6, gomobile v0.1.4, JDK 17, NDK 28.0.13004108 зафиксированы для совместимости этой ветки, а не как рекомендация новейших безопасных версий для production.

Установка gomobile идёт из cmd/gomobile; неподдерживаемый -tags программе build_libbox не передаётся. Протоколы и build-tags берутся из штатного сборщика sing-box. Собираются arm, arm64, amd64. Проверяются Java-binding Libbox и libbox.so всех трёх ABI. AAR кэшируется с ключом toolchain/source, без fallback на другие версии, и отдельно выгружается артефактом. Первый запуск тяжелее последующих; при очистке кэша ядро собирается снова.

Эти шаги не исправляют автоматически ошибки Kotlin, Gradle или несовпадения native API в будущих ZIP. При обновлении проекта, AGP/SDK или версии ядра workflow может потребовать согласованных изменений. Сборка на GitHub ещё не запускалась автором этого файла.

## Получение APK

Откройте успешный запуск → Summary → Artifacts → `Cyrus-debug-APK-<номер>`.

GitHub скачает ZIP артефакта, его нужно распаковать. Для большинства современных телефонов используйте APK с `arm64-v8a` в имени; `universal` крупнее и включает все три архитектуры. В артефакте также есть SHA256SUMS.txt и BUILD-INFO.txt. Точный выбранный исходный ZIP и его SHA-256 записаны в Summary.

Это устанавливаемые DEBUG APK, не production release. Debug-keystore кэшируется для повторных установок, но кэш может быть удалён/вытеснен. Он не заменяет постоянный релизный ключ подписи. Подпись ранее установленного приложения может отличаться уже при первом CI-запуске. При несовпадении подписи не удаляйте старое приложение без резервного экспорта нужных ключей; штатное обновление требует прежнего signing key.

Если сборка упала: откройте первый красный шаг, скопируйте текст ошибки и ближайшие строки. Не присылайте приватные ключи, конфиги VPN, токены или signing keystore. Пришлите compile/lint-ошибку, чтобы исправить конкретную причину.
