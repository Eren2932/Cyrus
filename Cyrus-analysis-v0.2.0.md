# Cyrus 0.2.0 — разбор исходника и выполненная переработка

Дата подготовки: 12 сентября 2026. База — опубликованный в Cyrus архив `kentra-phase1.zip`. Визуальный ориентир — публичный ZiziPlayer, его mobile changelog и desktop source 0.3.4-preview. Это отчёт об изменениях исходного кода, а не сертификат готовности APK.

## 1. Что фактически было в репозитории

В первом полученном снимке Cyrus были только три Markdown-документа. После сообщения владельца был повторно загружен репозиторий: появился `kentra-phase1.zip` с Android-проектом. Именно этот код использован как база. Сохранены 16 Gradle-модулей, Kotlin/Compose, Room, DataStore, Koin, Ktor, доменные модели и значительная часть тестов.

Положительная сторона исходника — разделение экранов, репозиториев, парсера и VPN-процесса. Это хорошая отправная точка, поэтому проект не заменён монолитом или браузерной демонстрацией. Но документация заметно опережала реализацию: описывала готовые гарантии, которых в коде не было.

## 2. Критические находки

| Находка | Почему важно | Изменение |
|---|---|---|
| `SimulatedVpnEngine` выдавал случайный трафик | Пользователь мог принять это за рабочую защиту | Симулятор удалён из production; готовность ядра проверяется до VPN consent |
| `Connected` публиковался до `engine.start()` | Интерфейс сообщал успех до создания соединения | Публикация перенесена после успешного старта; в поставляемой сборке движок недоступен |
| UUID, password и sub-URL хранились открыто | Утечка базы раскрывала секреты | Добавлены Keystore/AES-GCM и преобразование старых записей |
| Неизвестные TLS-поля могли сбрасываться в значения по умолчанию при ошибке чтения | Повреждение данных маскировалось как корректная конфигурация | Десериализация теперь завершается ошибкой, без тихого отключения настроек |
| Обновление сначала удаляло старые ключи, затем вставляло новые вне транзакции | Сбой мог оставить пользователя без ключей | Транзакционная замена профилей и метаданных источника |
| URL проверялся через `startsWith("http")` | Принимались невалидные строки, не было явной транспортной политики | URI-проверка и HTTPS-only |
| Ошибки refreshAll превращались в ноль | Неудача выглядела успешным обновлением | Сообщается число неудачных источников |
| Base64 MIME-декодер игнорировал мусор | Можно было принять повреждённый ввод | Строгий standard/URL-safe Base64, проверка UTF-8 |
| URLDecoder превращал `+` в пробел, userinfo декодировался повторно | Пароли и параметры искажались | Сохранение `+`, однократное percent-decoding |
| Парсер SS разбивал адрес по первому `:` | IPv6 не работал | Адрес читается через URI |
| TUIC был в enum, но не в парсере | Заявленная модель не означала реальный импорт | Добавлен TUIC share-link |
| Release использовал debug signing, lint игнорировал ошибки | Небезопасная основа для релизной раздачи | Debug signing удалён из release, lint error gate включён |

В исходных Compose-файлах также отсутствовали некоторые импорты `getValue` для делегированных state. Они добавлены. Отдельно исправлено подавление `CancellationException` в `appRunCatching`: отмена корутины больше не превращается в обычную ошибку приложения.

## 3. Перенос визуального характера ZiziPlayer

Подтверждённый фирменный оранжевый — **#F97316**, тёмный текст поверх него — **#1B0C00**. Для Cyrus выбраны матовый чёрный фон, поверхности **#101010**, контролы **#1B1B1B**, основной текст **#F6F7F8**, вторичный **#9A9A9A**. Источники указаны в `PROVENANCE.md`.

Переработаны не только цвета. Добавлены крупные заголовки с короткими пояснениями, выраженная иерархия карточек, тонкие границы, более свободные отступы, собственные Canvas-иконки вместо первых букв вкладок, акцент выбранного профиля, расширенная кнопка добавления, нижняя панель импорта и подробные сведения о ключе. Цена на экране подписки теперь главный элемент карточки, а не надпись на неработающей кнопке.

Навигация использует fade и небольшой горизонтальный сдвиг. Отклик — 160 мс, переход экранов — 260 мс; токен плавного завершения — 340 мс. `FastOutSlowInEasing` и 340 мс подтверждены в Zizi desktop-коде; 160/260 мс — собственная адаптация Cyrus, не заявление о точном копировании всей мобильной анимационной системы. Состояние вкладок сохраняется средствами Navigation. Нажатие центрального элемента сопровождается коротким scale-откликом; бесконечной анимации в покое нет.

Список ключей построен на LazyColumn с устойчивыми IDs, фильтрация кэшируется по входным данным. Парсинг, файловый ввод и основная работа с шифрованием вынесены с UI-потока. Это инженерные меры, но **замеров FPS и времени кадра не было**. Не заявляется визуальное совпадение с Zizi 1:1 или проверенная плавность на слабом телефоне.

## 4. Новая работа с ключами

Ввод больше не ведёт сразу к слепому сохранению. Для локальных ключей сначала показывается отчёт: сколько распознано, сколько повторов и какие строки не импортируются. Только после подтверждения записываются распознанные записи. Неправильная строка не раскрывается в сообщении об ошибке целиком.

Добавлены библиотека с поиском по имени/серверу, фильтры протоколов, выбор активного профиля, редактирование имени, TLS-предупреждения, сведения о протоколе/сервере/SNI, раскрытие оригинального ключа, явное копирование и экспорт через системный выбор файла. Удаление требует подтверждения. При удалении выбранного ключа выбирается оставшийся; удаление постороннего профиля больше не вызывает безусловный disconnect.

Поддержаны перечисленные в матрице URI-форматы, mixed-case схемы, UUID-проверка, допустимые порты, IPv6, обычный и URL-safe Base64, SS legacy и SIP002, Hysteria2/Hy2, TUIC. Оригинальная ссылка и дополнительные поля сохраняются, а не исчезают при преобразовании в упрощённую модель. Это особенно важно для XHTTP, plugins и параметров провайдеров.

**«Любые ключи» не означает буквально любой существующий VPN-формат.** WireGuard, OpenVPN, JSON/YAML-конфиги и QR-декодирование не реализованы. Некоторые расширения сохраняются, но не исполняются; пример — XHTTP. Такой формат не маскируется под поддерживаемый tunnel adapter.

## 5. Подписки и хранилище

Обновление источника ограничено размером ответа и временем ожидания. Ошибка загрузки, неверный формат или пустой набор не удаляют прежние профили. Новые профили и метаданные источника записываются в одной транзакции. Устойчивый идентификатор на основе источника и ссылки помогает сохранить выбор при повторном обновлении неизменённого ключа. При реальной ротации выбор переводится на один из новых профилей.

Можно обновить один источник, обновить все, увидеть время синхронизации/ошибку и удалить источник с его ключами. Не выполняется фоновое обновление по расписанию — это отдельная задача для WorkManager и политики питания/сети.

Секреты шифруются перед записью Room. При этом полная база не превращается в непрозрачный контейнер: часть метаданных остаётся открытой. Миграция подготовлена в коде, но **обновление старого APK и Keystore-тесты на устройстве ещё обязательны**. Правила и риски вынесены в `SECURITY.md`.

## 6. Что сделано с магазином

Сохранён исходный прайс: **1 месяц — 199 ₽ / 3 устройства; 3 месяца — 499 ₽ / 3 устройства; 12 месяцев — 1499 ₽ / 5 устройств**. Трёхмесячный план выделен; цена за весь период и расчётная месячная цена разделены.

Вместо кнопок, которые всегда отвечали «на этапе 4», экран показывает настоящий локальный каталог и прямое объяснение: продажи не открыты. Есть рабочий переход к добавлению стороннего ключа. Никакие деньги не принимаются, fake-активация не создаёт entitlement, случайный URL не отправляет пользователя якобы на оплату.

Backend и договорённости с платёжным провайдером в исходнике отсутствуют. В этом ZIP они не придуманы. Перед продажами нужны серверная авторизация, планы из control-plane, заказы с идемпотентностью, проверенные webhooks, персональные ключи, возвраты/продления и юридические документы. Внешний checkout сам по себе не гарантирует соответствия правилам Google Play — это зависит от канала, региона и актуальной политики.

## 7. Переименование без ненужной потери данных

Продукт, проект, тема, Application, NavHost, VPN service class и имя CI-артефакта стали Cyrus. Старые package namespaces и application ID сохранены сознательно: механическое `dev.kentra` → `dev.cyrus` создаёт риск отдельной установки и потери доступа к прежней базе. Имя SQLite и DataStore также осталось прежним. Наличие одинакового ID не заменяет требование одинакового сертификата подписи.

## 8. Что проверено и что не проверено

Запущены **23 статические проверки исходников**: парсинг XML/TOML, структура модулей, баланс разделителей Kotlin, отсутствие production-симулятора и stage-заглушек, ключевые настройки шифрования, транзакции, TLS-политика, порядок публикации Connected, подпись релиза и сохранение original link.

В дереве теперь **52 JUnit-тестовых метода**, включая новые проверки URI/Base64/IPv6/плюсов/percent-encoding/дубликатов, сохранения дополнительных параметров, импорта и отмены. Они **не были выполнены**: в the Computer нет Gradle, Kotlin compiler, Android SDK, эмулятора и adb. Статический checker не является компилятором и не гарантирует успешную сборку. CI подготовлен, но запуск в GitHub владельца не выполнялся.

Поэтому нет приложенного APK, подтверждённого размера APK, скриншотов с устройства, результатов инструментальных тестов, проверки HTTP-провайдеров или VPN/DNS-тестов. Полная информация — в `VALIDATION.md`.

## 9. Что в прежних трёх документах требовало поправки

Архитектура смешивала план и факты. Утверждение, что реальный libbox подключается «одной строкой», неверно как критерий готовности: нужны API адаптера, TUN FD, socket protection, DNS bootstrap, reconnect, уведомления, native lifecycle, совместимость схем и тесты. Поддержку XHTTP конкретной версией выбранного ядра также нельзя предполагать без проверки.

Числа размера APK в `APK_SIZE.md` — оценки, а не измерения этой сборки. «Физический минимум 10 МБ» не является универсально доказанным пределом. Объём зависит от движка, тегов, ABI, версий зависимостей и упаковки; R8 не уменьшает Go-ядро как Kotlin bytecode.

Стоимость серверов, «30–60 пользователей на VPS» и маржа из backend-документа — бизнес-гипотезы. Они зависят от нагрузки, скорости порта, трафика, географии, DDoS/abuse и поддержки. Их нужно проверять нагрузочным тестом и фактической экономикой, а не использовать как обещание покупателю.

Исходные документы сохранены в `docs/history/`. Актуальные краткие версии описывают реально поставляемую архитектуру, отсутствие сетевого ядра и отсутствие backend.

## 10. Приоритет следующего инженерного прохода

Сначала необходимо прогнать Android CI и исправить все возникающие compiler/lint/test ошибки, затем проверить интерфейс на маленьком экране и с увеличенным шрифтом. Следом — Keystore и миграция старого приложения, реальные subscription endpoints и сценарии ошибок сети.

После этого выбирается конкретный native backend и версия. XHTTP может потребовать другого движка/адаптера, чем выбранный для остальных форматов. Нужны реальное установление TUN, protect(), DNS/IPv6/leak tests, Wi-Fi ↔ LTE, doze, восстановление процесса, отключение и отзыв разрешения. Только успешные испытания позволяют снять маркировку «трафик не защищён».

Продажи открываются отдельно — после работоспособного сервиса и подтверждённой серверной выдачи индивидуальных ключей. Этот ZIP существенно развивает менеджер ключей и интерфейс, но не маскирует отсутствие двух главных внешних систем: VPN-ядра и биллинга.
