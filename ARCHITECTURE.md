Документ-источник истины. Если код и этот файл расходятся — прав этот файл, код правим.

Версия: 0.1 (итерация 0+1). Дата: 2026-09-12.

---

## 1. Что мы строим

**Гибридный VPN-клиент + конфигуратор + магазин подписок.**

Три роли в одном приложении:

1. **Конфигуратор.** Пользователь вставляет любой ключ, купленный где угодно:
   `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://`, QR, файл, или ссылку на
   подписку (http/https). Всё работает бесплатно и без регистрации. Это точка входа и трафик.
2. **Клиент.** Подключение, статистика, выбор локации, per-app routing, kill switch.
3. **Магазин.** Покупка нашей подписки на 1/3/12 месяцев. Это деньги.

Порядок платформ: **Android (Kotlin + Compose) → Desktop (Compose Multiplatform) → iOS (позже, там свой NetworkExtension)**.

## 2. Ключевое бизнес-решение: почему НЕ перепродаём один общий ключ

Исходная идея: купить «безлимитный ключ» за 200–500 ₽ и продавать его многим клиентам.

Сначала терминология: «ключа без лимита памяти» не существует. Существуют подписки без лимита
**трафика** и без лимита **одновременных устройств/IP**. Технически один VLESS-ключ (один UUID)
действительно может использоваться десятками людей одновременно.

Почему это плохая основа для бизнеса:

| Проблема | Последствие |
|---|---|
| Провайдер видит один аккаунт с 50 разных IP | Бан аккаунта — одновременно отваливаются все 50 клиентов |
| Нет учёта по пользователю | Нельзя ограничить, отключить, продлить, посчитать трафик конкретного человека |
| Один абьюзер (торренты, спам, сканы) | IP в блоке — страдают все |
| Ключ утёк | Клиент раздал друзьям бесплатно, ты этого не видишь |
| Нет управления локациями | Нельзя продавать «NL / DE / TR на выбор» |
| Ты посредник без актива | Провайдер поднял цену, сменил ключ, закрылся — продукт умер за ночь |

**Решение: те же 200–500 ₽, но в свою инфраструктуру.**

- VPS в NL/DE/FI (Hetzner, Aeza, PQ Hosting) — ровно эти деньги в месяц.
- Панель: **Remnawave** (современная, API-first, мультинодовая) или Marzban / 3x-ui.
- Протоколы: **VLESS + Reality (XTLS-Vision)** как основной, **WS/XHTTP + TLS за CDN** как
  резервный транспорт для жёсткого DPI.
- Каждому клиенту — **свой UUID и своя subscription-ссылка**: лимиты, срок, статистика, отключение.

Экономика: один VPS за 300 ₽ спокойно держит 30–60 активных пользователей.
Себестоимость 5–10 ₽ на пользователя, продажа 150–250 ₽/мес. Маржа 90%+, контроль 100%.

Общий ключ допустим ровно в одном месте: **trial на 24 часа** на отдельной «ноде-жертве»,
которую не жалко потерять.

## 3. Монетизация и дистрибуция (влияет на архитектуру, поэтому решено заранее)

- **Платежи вне приложения.** Google Play требует Play Billing и комиссию за цифровой контент,
  купленный внутри приложения, а VPN-приложения и без того проходят усиленную проверку.
  Поэтому: веб-чекаут или Telegram-бот (ЮKassa, Cryptomus, Telegram Stars), а в приложении —
  **только активация кода / вход**. Это заложено в `BillingRepository.createCheckout()`,
  который возвращает URL внешней страницы.
- **Каналы раздачи:** Google Play (клиент без встроенных покупок) + RuStore + прямой APK
  с автообновлением. Не строим всё на Play: реджект вероятен, и он не должен убивать бизнес.
- **Юридика до первого рубля:** оформление приёма платежей, ToS с запретом абьюза, политика
  конфиденциальности (Data Safety в Play заполняется по факту: мы не логируем трафик).

## 4. Стек: что предложил друг и что я изменил

Предложение было: Clean Architecture + MVI + модуляризация; Compose, Hilt, Coroutines/Flow,
Room + DataStore, Ktor, libbox, Turbine + MockK.

База правильная. Изменения:

| Слой | Было | Стало | Почему |
|---|---|---|---|
| DI | Hilt | **Koin 4** | **Hilt не работает в Kotlin Multiplatform.** Цель — десктоп на Compose Multiplatform, значит на Hilt пришлось бы переписывать DI во всём проекте |
| Core | libbox | **libbox (sing-box)** | Единственный разумный выбор: VLESS/Reality/XHTTP/Hysteria2/TUIC из коробки, активная разработка |
| Storage | Room + DataStore | Room 2.6 + DataStore | Оставлено. При переходе на KMP — Room 2.7 KMP или SQLDelight |
| Network | Ktor client | Ktor 3 + OkHttp engine | Оставлено |
| UI | Compose + MVI | Compose + собственный `MviMachine` (40 строк) | Никаких MVI-фреймворков: своё ядро понятно, тестируемо и переносимо в KMP |
| Tests | Turbine + MockK | + `kotlinx-coroutines-test`, fake-объекты вручную в чистых модулях | MockK не KMP-совместим; в `:domain` и `:core` используем фейки, MockK — только в Android-модулях |

**Чего в исходном предложении не было, а без этого проект не существует:**
процессная модель VPN, генерация sing-box конфига, слой подписок, биллинг/энтайтлменты,
шифрованное хранилище секретов, экран диагностики.

## 5. Дерево модулей

```
:app                      Android-хост: Koin, навигация, сборка всех фич
:domain                   ЧИСТЫЙ Kotlin: модели, UseCase, интерфейсы репозиториев
:core:common              AppError, DispatcherProvider, Logger, redactSecrets()
:core:mvi                 MviMachine: Store / Intent / State / Effect
:core:ui                  MviViewModel, CollectEffects, форматтеры
:core:designsystem        тема, токены, ConnectOrb, KentraCard, StatPill
:core:database            Room: сущности, DAO, БД
:core:datastore           SettingsStore (не секреты)
:core:network             Ktor HttpClient, ApiConfig
:data                     реализации репозиториев + мапперы + Koin-модуль
:vpn:link                 парсеры ключей (pure Kotlin, полностью покрыты тестами)
:vpn:config               типизированная модель sing-box + ConfigFactory
:vpn:service              VpnService, VpnEngine, TunnelBus, TunnelController
:feature:home             коннект, трафик, активный ключ
:feature:profiles         список ключей, импорт, подписки
:feature:store            тарифы, внешний чекаут, активация кода
```

**Правила зависимостей (нарушение = ревью не пройдено):**

- `:feature:*` → `:domain`, `:core:*`. **Никогда** → `:data:*`, **никогда** друг на друга.
- `:data` → `:domain`, `:core:*`, реализует интерфейсы из `:domain`.
- `:domain` не зависит ни от чего: ни Android, ни Ktor, ни Room. Проверка простая —
  в `:domain` не должно быть ни одного `import android.*`.
- `:app` — единственный модуль, который знает про всех. Здесь живут UseCase и ViewModel-фабрики.
- Только `:vpn:service` знает про существование Go-ядра.

## 6. Три места, где такие проекты умирают, и что мы с ними сделали

### 6.1 Процессная модель VPN

Падение ядра не должно убивать UI, а UI может быть убит системой при живом туннеле.
Поэтому единственная правда о туннеле — `TunnelState` внутри VPN-слоя, UI только подписывается.

```kotlin
sealed interface TunnelState {
    data object Idle
    data object Preparing
    data class Connected(val profileId: String, val sinceEpochMs: Long)
    data object Stopping
    data class Failed(val reason: String, val retryInMs: Long?)
}
```

UI **никогда** не хранит состояние туннеля как своё. Иначе получаем классический баг
«кнопка говорит Connected, интернета нет».

- Итерация 1: сервис в основном процессе, состояние через `TunnelBus`.
- Итерация 2: `android:process=":vpn"` + AIDL/Messenger. `TunnelBus` становится клиентом
  канала, **остальной код не меняется** — за пределами пакета никто не читает состояние напрямую.

### 6.2 Генерация конфига sing-box

Единственное место, где `VpnProfile` превращается в JSON — `:vpn:config/ConfigFactory`.
JSON никогда не собирается конкатенацией строк: одна лишняя запятая — мёртвый туннель
на телефоне клиента, который невозможно отладить удалённо.
Покрыт тестами: протоколы, транспорт, TUN-опции, отсутствие утечки DNS в прокси.

### 6.3 Подписки вместо ключей

В базе хранится не только ключ, а **источник**: `SubscriptionSource(url, lastSync, profileCount)`.
Обновление по расписанию и при ошибке коннекта, стратегия «сервер — источник истины»
(старые ключи источника удаляются, новые записываются).

Это даёт **ротацию ключей и смену нод без обновления приложения**. Когда ноду забанят,
ты меняешь её в панели, а у клиента всё продолжает работать.

## 7. MVI-контракт: один шаблон на все экраны

```kotlin
data class HomeState(...) : MviState
sealed interface HomeIntent : MviIntent
sealed interface HomeEffect : MviEffect   // одноразовые: навигация, снекбар, запрос разрешения

class HomeViewModel(...) : MviViewModel<HomeIntent, HomeState, HomeEffect>(HomeState()) {
    override suspend fun handle(intent: HomeIntent) { ... }   // единственный метод, который пишет фича
}
```

Правила:

- `reduce { }` — чистое преобразование состояния, без side-эффектов.
- Side-эффекты — только через UseCase внутри `handle`.
- В `@Composable` нет ни одной строки логики: экран получает `state` и отдаёт `dispatch`.
- Android-диалоги не живут в data-слое: если нужно согласие на VPN, `TunnelController`
  падает с `AppError.Permission`, а фича превращает это в `HomeEffect.RequestVpnPermission`.
  Именно поэтому ViewModel тестируется без Robolectric.

## 8. Тесты: что покрываем обязательно

| Модуль | Что и чем |
|---|---|
| `:vpn:link` | все форматы ключей + base64-подписка + мусор на входе (JUnit) |
| `:vpn:config` | маппинг протоколов, TUN-опции, DNS не уходит в прокси, чистота JSON |
| `:core:mvi` | редьюсер и одноразовость эффектов (Turbine) |
| `:data` | round-trip маппера: домен → БД → домен без потерь |
| `:feature:*` | ViewModel: коннект, дисконнект, отсутствие согласия на VPN (Turbine + фейки) |
| позже | Paparazzi (скриншот-тесты), Compose UI tests, golden-конфиги |

CI (`.github/workflows/android.yml`): `gradle test` → `gradle :app:assembleDebug` →
артефакт APK + отчёты тестов. Gradle ставится через `gradle/actions/setup-gradle`,
поэтому **бинарный gradle-wrapper.jar в репозитории не нужен**.

## 9. Вес приложения: честная математика

Ожидание «2–5 МБ» верно **только для UI-оболочки без ядра**.

| Состав | Release APK (arm64, R8 + shrinkResources) |
|---|---|
| Compose + Material3 + Navigation + Room + Ktor + Koin (итерация 1, движок-симулятор) | **2.5–4 МБ** |
| + libbox (sing-box, gomobile): Go-runtime и протоколы | **+10–16 МБ** |
| Итого per-ABI arm64 | **13–19 МБ** |
| Универсальный APK (3 ABI) | 35–50 МБ |

Для сравнения: v2rayNG и Hiddify — 30–70 МБ. Любой клиент с VLESS/Reality тянет Go-ядро
(sing-box и xray оба на Go), поэтому 10 МБ — это физический пол, а не наша недоработка.

Чем жмём (уже заложено в конфиг сборки):

1. **ABI-сплиты / App Bundle** — пользователь качает одну архитектуру, а не четыре. Минус 60–70%.
2. **Сборка libbox с нужными тегами:** `-trimpath -ldflags "-s -w"` (минус ~25%),
   отказ от `with_gvisor` в пользу `stack=system` (минус ~4 МБ), только те протоколы, что продаём.
3. **R8 full mode + shrinkResources** (включено), `resourceConfigurations = ru, en`.
4. **Никакого `material-icons-extended`** и никаких Firebase/аналитик-SDK.
5. `ui-tooling` только в `debugImplementation`.

Целевой SLA по весу: **≤ 15 МБ per-ABI release** после интеграции ядра.

Подробнее — `docs/APK_SIZE.md`.

## 10. Безопасность

- Ключи, токены и subscription-URL — в шифрованном хранилище (`:core:crypto`, Keystore),
  **не** в DataStore. В итерации 1 секретов ещё нет.
- Бэкап отключён: `allowBackup=false` + `data_extraction_rules.xml` исключает БД и prefs,
  чтобы ключи не улетели в облако.
- Логи проходят через `redactSecrets()`: UUID и ссылки в логах не появляются никогда.
- Certificate pinning для control-plane (этап 4).
- Анти-абьюз на сервере: привязка к устройствам, лимит сессий, ротация UUID при подозрении.
- Мы не логируем трафик пользователей. Это и позиция, и требование Data Safety.

## 11. Бэкенд (минимальный, но обязательный)

Без него магазин не существует, поэтому он не «потом», а этап 4.

- **Ktor Server + PostgreSQL** (один язык с приложением) или тонкий BFF поверх API Remnawave.
- Auth: device-id + вход через Telegram или e-mail, JWT + refresh. Без пароля на старте.
- Эндпоинты: `/v1/plans`, `/v1/orders` (внешний чекаут + webhook), `/v1/activate`,
  `/v1/me` (энтайтлмент), `/v1/subscription` (отдаёт sub-URL), `/v1/nodes`, `/v1/telemetry`.
- Деплой: Docker Compose + Caddy на отдельном VPS. **Control-plane и ноды — разные машины:**
  забанят ноду, панель и платежи продолжат работать.

Подробнее — `docs/BACKEND.md`.

## 13. Топ-5 рисков

1. **libbox/gomobile** — вес, время сборки, ломающие изменения схемы конфига.
   Ответ: пиннить версию sing-box, golden-тесты конфига, кэш артефакта в CI.
2. **Google Play** — вероятен реджект. Ответ: RuStore + APK-канал готовы заранее.
3. **Блокировки DPI** — Reality может перестать проходить. Ответ: второй транспорт
   (WS/XHTTP за CDN) и быстрая смена нод через подписку.
4. **Поддержка** — без экрана логов и кнопки «отправить диагностику» утонешь в «не работает».
5. **Юрисдикция и платежи** — решить до первого рубля, а не после.
